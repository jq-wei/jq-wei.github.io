The task. Exploratory task on a new plant (not one of the benchmark tiers reported in the paper; see docs/soft_arm_spec.md): a planar soft continuum arm whose material (stiffness, damping, actuation hysteresis, creep, chamber gains) is drawn per seed from stated ranges and never reported, sensed by a 25 Hz tip camera only, with pressure lag, one-sided actuation and a folded, near-singular static map.

more

Six tip targets per seed, each to be held within 10 mm for 2 s inside its 10 s window. A one-shot inverse of the nominal model drifts out under hysteresis and creep; the design has to keep correcting from the tip error alone. Gate fine on 0.9 of the seeds; the fast rung (every hold complete within 5 s) is open to a better design than the oracle, which reaches it on half the seeds.

Gate. per-seed success is the `fine` rung of this benchmark's ladder ['safe', 'coarse', 'fine', 'fast'] (`--success-mode fine`), not the evaluator's default flag; the task is solved when the success rate over the grader's held-out seeds is `>= 0.9`

The agent's final message

The controller in `/app/work/controller.py` passes the `fine` rung on all 360 nominal seeds I ran (0–359). On every one of them, all six targets were held within 10 mm, and the worst best-2-second hold error on any target was 2.98 mm. The official evaluator on seeds 0–4 reports `solved=True` and passes every rung, including `fast`. The grader uses other seeds, so this is an estimate of its result, not a guarantee. The session took about 19 of the 60 minutes. **How it works** - **Starting command:** when a new target appears, the controller searches the nominal arm's static map for the commands that put the tip there. If two arm shapes reach the target about equally well, it picks the one closest to its current command, so the arm doesn't jump between the S and C shapes. - **Correction:** on each new camera frame, it turns the tip error into a command change using the map's local slope. The slope inverse is damped so it stays bounded below the mount, where the map is nearly singular. It adds that change to the command bit by bit, at gain KI = 1.0 per second. This absorbs this seed's unknown stiffness, chamber gains, hysteresis and creep. - **Pressure range:** below full command it matches `chamber_commands` with a 0.1 co-contraction bias. Beyond that it lowers the opposing chamber below the bias, so the full pressure difference is still available. **What the gain tests showed** - With KI = 1.5 one nominal seed failed (seed 25: low damping, oscillating 2–25 mm about the targe…

Controller family: other: static-map feedforward + Jacobian integral feedback

On each new target it sets the pressure-difference command to the inverse of the nominal static tip map, then on each fresh camera frame integrates the tip error through a damped Jacobian pseudo-inverse (with step clamp) to correct the command, which is mapped to four chamber pressures with co-contraction bias.

Controller family: other: model-based feedforward + task-space PID with online gain identification

The controller inverts a precomputed nominal static tip map for feedforward (scaled by an identified gain g and ramped on target changes), adds a filtered task-space PI plus velocity damping through a damped Jacobian pseudo-inverse, and wraps the resulting chamber pressure commands in a fast inner pressure feedback loop.
